# 🌍 EarthPulse

**Dual-stream planetary intelligence.** EarthPulse tracks planetary *degradation*
and *regeneration* in parallel — the Crisis Stream and the Regeneration Stream —
builds historical depth day by day, projects future scenarios, and turns the
balance between the two into actionable earth-care advice.

Part of the Terra Alta portfolio. Stack: **React 18 · Vite · TypeScript ·
Tailwind v3 · Supabase · Vercel**, with scenarios and advice generated by the
**Claude API** (`claude-sonnet-4-6`).

> 💻 **Working on this app from another computer?** See **[SETUP.md](SETUP.md)** —
> a beginner-friendly guide to cloning and running EarthPulse, via GitHub Desktop
> (buttons) or the Terminal.

---

## What's in the MVP

- **Dual-stream dashboard** — Crisis (amber) and Regeneration (green) panels side
  by side, each with 3–4 indicators, sparklines, trend %, and a planetary balance
  meter.
- **`earth_snapshots` table** — one row per indicator per day, so history
  accumulates over time.
- **Scenario panel** — Claude reads the last 30 days and generates three futures:
  business-as-usual, moderate earth-care adoption, accelerated regenerative
  transition.
- **Advice panel** — contextual guidance for Individual / Community / Policy
  audiences, weighted by the current stream balance.
- **Daily cron** — a Supabase edge function fetches fresh indicator data once a day.

Indicators are sourced from **Global Forest Watch**, **OpenAQ**, **NASA EONET**,
and **GBIF**.

> The app runs immediately on deterministic **sample data** and offline scenario/
> advice fallbacks — no configuration required to see it working. Wiring up
> Supabase + the edge functions swaps in live data and live Claude output.

## Architecture

```
Browser (React) ──reads──▶ Supabase: earth_snapshots (last 30d)
      │
      ├──POST /functions/v1/scenarios ─▶ Claude ─▶ 3 future scenarios
      └──POST /functions/v1/advice    ─▶ Claude ─▶ tailored advice

Supabase cron (daily) ─▶ /functions/v1/daily-fetch ─▶ GFW · OpenAQ · EONET · GBIF
                                                     └─▶ insert earth_snapshots
```

The Claude API key lives **only** in edge functions — never in the browser.

## Full setup (live data)

### 1. Database

Apply the schema from [`supabase/migrations/0001_earth_snapshots.sql`](supabase/migrations/0001_earth_snapshots.sql)
— via the Supabase SQL editor, the CLI (`supabase db push`), or the MCP.

### 2. Frontend env

Copy `.env.example` → `.env` and set:

```
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon key>
```

### 3. Edge function secrets

```bash
supabase secrets set ANTHROPIC_API_KEY=sk-ant-...
# optional:
supabase secrets set OPENAQ_API_KEY=...      # enables air-quality indicators
supabase secrets set GFW_API_KEY=...         # enables Global Forest Watch indicators
supabase secrets set ANTHROPIC_MODEL=claude-sonnet-4-6   # default
```

### 4. Deploy functions

```bash
supabase functions deploy earthpulse-scenarios
supabase functions deploy earthpulse-advice
supabase functions deploy earthpulse-daily-fetch
```

> Functions are prefixed with `earthpulse-` so EarthPulse can share an existing
> Supabase project (e.g. `roda`) without colliding with that project's own
> functions. The `earth_snapshots` table lives in `public` under its distinctive
> name — it coexists with the host project's tables and requires no downtime to add.

### 5. Schedule the daily fetch

Fill in the two placeholders in
[`supabase/migrations/0002_daily_cron.sql.template`](supabase/migrations/0002_daily_cron.sql.template)
and run it in the SQL editor. It uses `pg_cron` + `pg_net` to hit `daily-fetch`
at 06:00 UTC. Run `daily-fetch` once manually to seed the first data point.

## Data sources & keys

| Indicator | Source | Key needed |
|---|---|---|
| Deforestation alerts | Global Forest Watch | `GFW_API_KEY` |
| Air pollution (PM2.5) | OpenAQ | `OPENAQ_API_KEY` |
| Active natural events | NASA EONET | — |
| Biodiversity observations | GBIF | — |
| Species observed | GBIF | — |
| Clean-air locations | OpenAQ | `OPENAQ_API_KEY` |
| Forest under restoration | Global Forest Watch | `GFW_API_KEY` |

EONET and GBIF work with no key, so the cron always produces data; OpenAQ and GFW
indicators activate once their keys are set. Each fetcher runs independently — one
failure never blocks the others.

## World Pulse (second area)

A second tab, **World**, reads the *human* systems pressing on the planet — nine
geopolitical forces, each with a tension score (0–10), a regeneration
counterpoint, a scenario lean (A/B/C/D) and a signpost timeline. It updates
**weekly** and, like Planet, renders fully from bundled seed data
([`src/data/worldSeed.ts`](src/data/worldSeed.ts)) with a "sample data" badge
when there's no backend. Switch tabs in the header (state kept in the URL hash,
`#world`).

**Live weekly updates (optional, needs a Supabase project):**
1. Apply [`supabase/migrations/0003_world_pulse.sql`](supabase/migrations/0003_world_pulse.sql)
   and [`0004_world_seed.sql`](supabase/migrations/0004_world_seed.sql).
2. Deploy the writer: `supabase functions deploy earthpulse-world-weekly`
   (needs `ANTHROPIC_API_KEY` in Supabase secrets; uses `claude-sonnet-5` + web search).
3. Set the frontend `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` so the World
   tab reads live rows instead of seed.
4. Schedule it: fill in and run [`0005_world_weekly_cron.sql.template`](supabase/migrations/0005_world_weekly_cron.sql.template)
   (Sundays 18:00 UTC).
5. Optional: `VITE_WORLD_REPORT_URL` adds a "full report" link to the weekly brief.

Manual trigger:
```bash
curl -X POST "https://<project-ref>.supabase.co/functions/v1/earthpulse-world-weekly" \
  -H "Authorization: Bearer <service-role-key>" -H "Content-Type: application/json" -d '{}'
```

> ⚠️ The `earthpulse-world-weekly` function is **untested** — the current build
> has no Supabase project, and the web-search tool version string
> (`web_search_20260209`) should be re-checked against Anthropic's current docs
> before the first real run.
